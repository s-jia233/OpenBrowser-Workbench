# 从本地编程原型到通用 Agent 产品

这里的“通用”指可扩展到不同项目、模型和受控工具，不是允许模型任意控制电脑。浏览器连接仍须符合所用服务的条款与额度。

## 第一批：会话可靠性（已实现）

- 自动保存用户任务、模型回复、历史轮次、文件选择、验证选择、实际执行结果和日志。
- 每个项目独立存储到 `.openbrowser/workbench-sessions.json`，每个项目最多保留40个会话（归档也计入）；达到上限阻止新建，允许继续原对话，请先备份并手动删除不需要的会话。已打开项目的记录分别保留，不再为了全局内存上限自动移除旧会话。单文件上限64 MB，超限报错，不自动删历史。
- 发送模型任务前持久化等待状态，执行文件事务前持久化应用中状态。
- 正常关闭服务时等待正在执行的文件事务和验证结束，并刷新保存队列。
- 重启恢复已完成的会话；尚未完成的任务暂停，旧连接和批准全部失效，不自动重发、执行或“补做”。
- 强制终止时若最后记录为应用中，明确提示文件状态未知，不能把它描述成已回滚。
- 应用前保存批准记录失败时，保持待审核状态，释放项目锁，不写文件，可修复存储后重新批准；不把保存失败交给模型重试。
- 每次实际应用记录文件结果（已应用/已回滚/回滚不完整/未写入/状态未知）及验证结果（通过/未运行/失败/环境异常/未知），保留各次尝试及追问历史。模型输出和脚本日志文字不能伪造回滚结果；旧记录无结构化数据时提示查日志，不补造“测试通过”。
- 已明确选择的验证脚本不存在、配置不可读取时，停止验证并回滚本轮文件修改，不静默跳过。逐项记录真实通过的脚本，先通过一项、后面失败时不把整组标成通过。
- 保存失败会反馈错误；文件损坏、格式不支持或所属项目不符时保留原文件并拒绝静默覆盖。
- 持久化内容不含访问令牌、实时会话编号、执行计划、文件批准指纹或重复的源码上下文。会话文本仍可能包含用户主动提交的敏感内容，当前未加密，发布源码包时必须排除 `.openbrowser`。

这不是完整的崩溃事务恢复。跨进程强制终止后的自动文件恢复仍需持久化变更集与事务日志；当前只保存对话并停止不确定操作。

## 第二批：模型与工具接口

1. 增加持久化配置与配置校验：后端、超时、上下文预算、只读工具额度、验证白名单。
2. 接入一个正式的 HTTP 模型后端，再验证浏览器与 HTTP 后端使用相同工作流。密钥不写入对话存储。
3. **已完成首批只读文件工具**：列目录、文字搜索和按行读取。修改代码模式无需手动勾选文件即可由模型发现相关代码，结果有范围与大小限制，调用和拒绝原因进入日志。搜索后必须读取源码，修改仍需人工审核。使用方式见 [文件发现工具](./FILE_DISCOVERY.zh-CN.md)。
4. 明确区分权限问题、环境故障、模型格式错误和额度错误；只有可修复错误进入有限重试。

验收：单模型完成读取、补读、提案、审核、执行、验证、失败反馈；替换模型后端不改变审批与安全规则。

## 第三批：强隔离与可恢复变更集

- 持久化每次变更的原始内容、操作清单和事务阶段，先写日志再修改文件。
- 增加明确的版本比较、恢复预览、冲突检查和人工批准回滚。
- 容器或受限执行器：默认断网、限制目录挂载、运行时间、内存与进程树；无法提供隔离时不能标成“安全沙箱”。
- ZIP 导入拒绝路径逃逸、链接、异常文件数和解压炸弹，只在新建目录解压。

验收：在各事务阶段注入进程中断，恢复结果可解释；测试脚本不能写出允许的边界。

## 第四批：多模型与子 Agent

- 在稳定单模型流程上增加用户明确允许的路由策略，不静默改变数据发送目的地。
- 子 Agent 先限于只读搜索、计划和测试分析；只有主工作流能生成待审核变更集。
- 预算、调用次数、人工暂停和审计覆盖每个子任务，不通过换账号或自动重发绕过服务限制。

## 发布门槛

在称为通用 Agent 产品前，仍需配置与迁移测试、自动化故障注入、真实后端兼容性验证、依赖与许可清单、干净安装包和独立测试项目。当前版本仍是持续完善中的本地原型。
