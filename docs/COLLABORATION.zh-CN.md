# 多模型方案比较与协作工作台（v0.6.1，人工批准实施）

入口：启动原工作台后，点击左侧「多模型协作」。原有单模型任务、连续追问和 Diff 审核保留。

## 一次会诊的流程

1. 输入共同任务和验收要求，在右侧选择需要的源码。最多8个文件，每个16000字，总上下文60000字。未选文件时只提供最多150个文件名，不代表模型读过这些代码。
2. 选择2–4个提案者和1个评审，可混用网页、手动传递和本机 Ollama 接口。确认内容可分享给所有参与者（包括评审）后开始。
3. 每个提案者收到完全相同的任务和源码快照。回复独立保存，不会直接执行其中的代码或文件操作。
4. 全部提案结束且至少两份成功后，自动交给评审。提供匿名方案编号、原始任务和同一份快照；缺失或失败明确标注，不伪造补齐。
   开始评审后候选方案冻结，不能再替换回复；需要补充新的候选内容时请新建会诊，避免报告与方案不一致。
5. 在方案卡片中勾选要采纳的方案，填写具体反馈，选择由谁生成统一草案。最多两轮反馈，不自动无限辩论。
6. 比较完成后，可在成功提案或最新统一草案中点击「确认方案并生成 Diff」。核对最新代码、实施草案、执行方式与验证项目后创建关联任务；模型重新读取当前代码生成 Diff，由人单独批准后才应用和验证。比较报告不能直接作为实施方案。
7. 「仅带入输入框」保留旧的手动整理方式，只复制到单模型输入框，不发送、不创建关联实施记录。

## 从方案到实施

流程：比较方案 → 确认实施 → 生成并审核 Diff → 批准应用 → 验证；验证失败后回滚本轮文件修改并有限反馈，新的 Diff 必须重新批准。

1. 在「确认方案并生成 Diff」弹窗中检查源文件状态：列出相对原快照已变化的所选文件；重新读取当前文件，不套用旧补丁。如果文件已移除或不可读取，阻止实施，先重新会诊。未附带源码时明确提示，执行模型须先使用只读工具补读。
2. 草案可人工调整或精简。只把共同任务、这份确认草案和最新上下文交给执行者，不自动发送所有候选和评审原文。原任务与生成的实施消息合计不得超过16000字，超限要求人工精简，不静默截断。
3. 执行方式默认为手动传递（不自动发送）；也可以明确选择某个就绪网页。网页领取、进度及回复只接受该实例/标签页，不会在断线时改发其他网页。请用独立新会话，遵守服务限制。Ollama 当前只参与提案/评审/融合，尚未接入文件执行闭环。
4. 人工勾选批准 Diff 后运行的项目验证脚本，展示实际脚本命令。临时副本仍有本机进程权限，并不是容器。没有选择验证脚本时不宣称测试通过。
5. 每次打开弹窗都必须重新确认发送内容与验证选择；确认不是写文件批准。确认后到创建任务之间源码或验证命令再次变化，将要求重新打开核对。重复提交同一确认只创建一份任务，不重复发送；改变配置需重新打开确认。
6. 实施任务保留会诊编号、来源方案、原快照和实施时的代码摘要。原会诊显示「关联实施任务」的真实状态，可打开任务审核 Diff/查看日志；任务中可「返回方案比较」。重新启动服务后保留关联，但中断调用暂停，旧 Diff 批准不恢复。
7. 沿用现有文件事务和验证闭环：验证失败会尝试回滚，最多三次方案尝试；每次新 Diff 仍等待人工批准。回滚失败明确报错，不声称恢复完成。「关联实施任务」、任务页和运行日志顶部显示实际文件结果与验证结果，明确区分已应用、已回滚、未运行测试、所选验证通过和状态未知；只表示所选脚本，不等于全部测试通过。旧任务没有结构化记录时仅提示查日志，不倒推验证结论。
8. 明确选择的验证脚本消失或配置不可读时不会静默跳过，回滚本轮修改后暂停，修复配置后重新审核。批准记录保存失败时仍停留在待审 Diff，项目文件不变，不会锁死后续操作。

同一时间只允许一个实施任务；先完成、拒绝或停止后才能生成下一份。正在执行或等待审核的关联任务未结束前不能删除会诊；删除已结束会诊不会删除实施对话、操作历史、模型网站聊天或导出文件。关联对话可继续追问，之后的问答完成不等于原代码已通过测试。

## 失败恢复、方案对照与导出

- 失败卡片可点击「重试 / 更换参与者」，只重发当前失败步骤，不重发其他成功方案，继续使用原项目快照。更换评审后，后续融合默认跟随新的评审。
- 每一步总共最多三次尝试（初次加两次人工重试）。重试前必须重新确认旧网页生成已停止，并确认内容发送范围；程序不会绕过服务额度或限流，也不会自动重试。达到上限仍可手动补交。
- 页面保留之前尝试的参与者和错误原因。重启恢复为暂停，允许人工重试或补交，不自动重放。已进入评审的候选方案、已被新融合步骤取代的旧报告不能再替换；已停止的会诊可用「复制配置新建」重新开始。
- 评审按固定 JSON 格式返回时，展示需求覆盖、优势、风险、源码依据/待核查、验证计划、可融合部分对照表，支持横向滚动。字段缺失、重复方案、捏造失败方案等不合规回复只展示完整原文，不自动修补、不生成虚假分数，也不重复调用模型。
- 「导出报告」下载 Markdown，包含结构化对照（如果有效）、全部回复、人工意见和尝试记录。默认不包含源码快照内容或完整发送提示词，但任务/回复仍可能复述敏感代码，分享前请人工核对。
- 「复制配置新建」复制共同任务、参与者及所选文件列表，创建时重新读取当前项目代码，不沿用旧快照；仍需重新确认共享。

## 未发送草稿

共同任务、参与者配置、手动回复、人工选择和反馈保存在当前浏览器的项目独立草稿中。刷新后进入「多模型协作」，从「本项目会诊」选择原记录，可恢复相应未发送内容；不会自动发送。共享确认始终不保存，也不会自动勾选。

草稿为本机浏览器明文数据，不是加密保险箱，不同步到其他设备。浏览器禁用存储或空间不足时会明确提示「草稿仅保留在当前页面」。已提交的草稿会清除；删除会诊同时清除其本浏览器草稿，但不会清除其他浏览器或已下载报告。

0.8.14 根据实际页面截图适配 assistant-message / DIL 渲染结构及稳定消息编号，读取完整多片段正文；同时修正单条消息完成标记造成回复流提前结束的问题。同会话两轮接收的集成回归已覆盖，仍不自动发送测试请求或应用修改。

每个提案者及评审使用不同的独立新会话标签页。可在同一平台打开多个标签页，但这不等于不同模型。扩展只报告实例编号、标签页编号和平台域名，不上传页面标题、完整聊天地址或账号信息。页面切换、关闭、重新加载后应核对参与者再开始。

每个步骤有独立会话编号，只有指定实例/标签页能领取、发送进度及回传回复。断线不会把任务交给其他标签页；已领取任务不会重复发送。4分钟未返回会标记失败，可人工补交回复。停止本地等待不一定能停止网页中的生成，请按需在网页手动停止。

自动化仅用于服务允许的用法；不绕过登录、验证、额度、限流或服务条款。不允许自动调用的服务可选择手动传递。首版没有新增云端正式 API 后端。

## 手动传递

不需要安装扩展。默认所有角色均为手动，避免误发到真实网页。

在每个步骤卡片复制「本步骤提示词」，交给自己选择的模型，然后在对应回复框粘贴文本并保存。提案、评审、融合均可手动完成；来源一律标记为未核实，不沿用某个网页身份。模型回复最长16000字，超长需要人工精简。

## 本机 Ollama 接口

读取固定回环地址 `http://127.0.0.1:11434/api/tags` 获取已安装模型，调用 `/api/chat`，每次只带本步骤消息，不共享其他模型的会话历史。模型必须事先安装，不会自动下载、登录或安装 Ollama。

接口固定为本机，不接受任意地址、不跟随重定向。显式 cloud 模型名称会拒绝；模型实际运行位置仍取决于本机 Ollama 配置，不能将“本机接口”当作隐私保证。单次最多4分钟，输出4096 token，不自动重试；截断、空回复、报错不当作成功方案。

官方接口说明：[聊天](https://docs.ollama.com/api/chat)、[列出模型](https://docs.ollama.com/api/tags)。

## 保存、安全与当前边界

- 本项目历史入口保存最多20次会诊；停止后可删除。会诊、所选源码快照、原文回复、反馈保存在项目 `.openbrowser/collaborations.json` 中，请按敏感数据管理。删除只删除本机会诊，不清理模型网站聊天或其他导出副本。
- 重启后恢复已完成的记录，中断步骤标为暂停/失败，不自动重新请求模型；可按上述规则人工重试或补交当前步骤。存储损坏时保留原文件，不能静默覆盖。
- 方案、报告和人类反馈作为待分析数据传递，评审没有写文件或执行命令的权限。提示词降低注入风险，但不保证能消除模型偏差；仍以人工判断和实际测试为准。
- 比较阶段不执行候选代码，不提供候选分支实测、测试成绩排行榜、自动拼接补丁或容器隔离。报告中的测试计划仍是未运行的建议；人工采纳后的实际应用、测试和回滚结果在关联实施任务日志中查看。
- 同一服务内的会诊与单模型执行分开进行。正在会诊时需先完成或停止，才能切换项目、开始单模型任务或恢复旧方案；可在一次会诊内并行多个提案，不同时开启多次会诊。
- 融合是根据人的选择重新生成一份统一草案，不是把所有方案逐段拼起来。
