# 按需上下文与补读

工作台和命令行 Agent 共用上下文优化，问答模式仍按所选附件回答。

## 默认发送内容

- 固定文件编辑规则、当前任务、精简历史摘要。
- 项目概况：脚本、依赖和最多 250 条文件路径；不扫描依赖缓存、构建产物、密钥或环境配置。
- 所选文件正文及原始行号。单文件、内容完整、超过 100 行，且明确要求修改开头或末尾时，默认发送对应 50 行。
- 全文分析、审查、重写、多文件或范围不明确的任务，不启用这类首尾裁剪。原有附件读取大小上限仍有效，超限会明确标记为截断，不能冒充全文。

每个文件带有 `partial`、`truncated`、`includedRanges`、`totalLines` 与源内容摘要 `sourceHash`。源内容不完整时，总行数和摘要为 null。

## 需要更多内容时

模型可以回复只读请求，不能同时携带文件修改或错误：

```json
{
  "conversationId": "当前任务的 UUID",
  "operations": [],
  "contextRequests": [
    { "path": "src/example.ts", "startLine": 1, "endLine": 100 }
  ]
}
```

省略 `startLine` 和 `endLine` 表示请求全文；指定行号时必须同时提供两项。路径相对于当前项目。

每个用户回合最多 2 次补读，每次最多 4 个不同文件，每段最多 200 行。单文件只读上限 1 MB，补读后的上下文 JSON 上限 140,000 字符。超过限制、读取被拒绝或信息仍不足时暂停，用户可调整附件或缩小任务后在原会话继续。

补读重新读取磁盘内容，替换相应文件的旧片段；不修改文件，不消耗原本 3 次纠错尝试，也不会绕过服务限额或自动切换模型。

## 保留的安全边界

- 拒绝项目外路径、符号链接、二进制内容、环境配置和密钥。
- 仅见过片段的文件禁止整文件覆盖，每轮只允许一个局部补丁，且修改范围必须位于已读内容内。
- 使用完整源摘要检查片段是否过期；截断前缀中的不完整行不能用于行号替换。
- 精确搜索必须非空且在实际文件中唯一；执行时不再对已解析 JSON 字符串二次转义。
- 补读全文后可以提出整文件替换，但仍必须经过 Diff 审核、变更校验、所选沙箱测试和原有失败回滚。

已有浏览器扩展可继续传递该协议，无需新增扩展权限。
