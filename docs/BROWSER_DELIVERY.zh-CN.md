## ChatGPT 连续追问与轮次释放（0.8.9）

针对「第一轮之后，第二轮连文字都没有进入 ChatGPT 输入框」检查发现并用模拟测试复现了以下生命周期问题；当前本地列表没有保留对应的 ChatGPT 失败轮次，因此这些是已验证的缺陷，不是对用户本次现场原因的唯一判定。

- **上一轮本地结束、扩展还在等待**：新任务到达及每 10 秒心跳时，用已有本地 session status 接口检查上一轮。只有服务明确返回 complete/error 才释放旧等待；连接异常不会当作取消。旧轮次未完成时继续排队，同一会话编号不重复提交。

## 本次定位

2026-10-22 的「修改readme文件」任务在 ChatGPT 页面发送阶段失败，原错误为 `Send button stayed disabled. The page did not accept the injected prompt.`。本地服务健康；任务没有进入 Diff 审核或文件应用。仅凭该日志不能断定是网站额度、页面编辑器变化，还是上传状态导致；没有重放这条真实任务。

代码检查发现并修复了以下兼容性与安全问题：

- 输入框：遍历可见、可编辑候选，ChatGPT 优先实际 ProseMirror 编辑器，跳过隐藏、禁用和只读元素；保留开放 Shadow DOM 查找。
- 受控文本框：仅调用原生 value setter，再发出包含文本和 composed 标记的 input 事件，避免二次 value 赋值让网页漏掉输入变化。

- 提交：只点击当前表单中可用的发送按钮，不用 Enter 或合成指针点击绕过禁用。通过新消息、生成状态或新回复捕获确认提交；输入框清空、按钮变灰不再单独算成功。点击后未确认时明确报告不确定，绝不自动再点一次。
- 保护：网页还在生成、有其他草稿或等待期间草稿变化时停止，不覆盖用户草稿；附件发送同样遵守这些规则。任务结束清理本轮回复捕获状态。

4. 检查网页登录、额度提示、附件是否上传完毕；保存或清空已有输入草稿。回到本地工作台刷新连接状态。
5. 确认网页中没有已经发出的同一请求后，再由你在原任务的「继续追问」中重试。重试会读取当前项目，不沿用旧 Diff 批准。

仅重启本地服务不会升级已安装的扩展。扩展已连接只证明桥接可达，不保证网站当前允许发送。不会自动刷新或升级浏览器里的扩展，也不会绕过登录、验证、限流或服务条款。

## 仍失败时

- 提示「未完整接收」：网页编辑器没有接受完整文本。刷新后仍失败，可在继续追问中改选「手动传递」，复制本轮完整提示词到网页，再将完整回复粘贴回工作台。
- 提示「ChatGPT 回复捕获不完整」：流式正文及当前轮页面补读都没能通过检查。新版错误包含片段长度、页面正文长度及未满足的条件。本轮停止且不会自动重发；先保存网页完整回复，更新扩展或改用手动传递，不要连续重试。
- 提示「未找到当前聊天输入区的发送按钮」：属于按钮识别/页面兼容性问题，不能据此认定是额度不足。重新加载当前源码的扩展并刷新 AI 网页；仍失败时可提供仅包含按钮标签的开发者工具截图，不要分享整页或聊天正文。
- 提示「已找到发送按钮，但持续不可用」：扩展找到了按钮，但没有强制发送。查看网页的登录、额度、生成或上传状态；等待或手动处理，不要连续重试。
- 提示「已点击发送，但未确认」：先查看网页聊天记录，可能已经发送，不要立即重发。若收到回复，先保存完整内容；当前失败轮次不能直接导入回复。需要继续时，在「继续追问」中选择手动传递，使用新一轮完整提示词取得对应回复，再回到工作台审核。不要把旧轮次回复粘到新轮次冒充本轮回复。
- 提示「已有草稿」或「草稿发生变化」：原网页草稿保留，先自行保存或处理，再重试。

## 验证边界

自动化测试运行真实扩展脚本，以模拟编辑器、受控文本框和页面状态检查输入及提交逻辑，包含用户截图中的中文按钮属性回归。0.8.9 还验证了同一模拟 ChatGPT 页面连续两轮输入与对应回复回传、前一轮取消、回传失败、短暂生成状态延迟、空回复及迟到回复；流式解析使用合成样本。测试不访问外部模型，不能代替当前 ChatGPT 网站的完整实测。中文按钮结构由用户提供的截图核对，并非直接读取了完整网页 DOM；本次未向真实 AI 发送测试任务，完整网站流程仍需更新扩展后由用户确认。
