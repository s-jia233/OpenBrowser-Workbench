# 本地 Web 工作台使用指南

## 0.6.6：指定网页、草稿与对话搜索

- **执行网页**：新任务和追问可指定本轮 AI 页面。只有一个已识别的就绪页面时自动绑定；有多个时必须选择。离线选择保留并提示重选，不会改发其他页面。需要扩展上报标签页信息；旧扩展未上报时仍保留兼容通道，建议更新到仓库中的 0.8.14。
- **文本草稿**：未发送的新任务、追问和手动回复保存在当前浏览器的本地存储中，按项目、会话、轮次及回复提示词隔离。刷新后打开原对话即可恢复；发送失败保留，发送成功清除对应草稿，删除对话同时清除其草稿。清空输入框可清除该文本。草稿不保存文件选择、模式和验证设置；恢复后请核对这些设置，不会自动发送、导入或应用。
- **对话搜索**：左侧按标题搜索最近或归档对话，忽略大小写，支持多个关键词。置顶顺序不变。

草稿存储可能包含你输入的代码和错误信息；仅存在当前浏览器，不跨浏览器同步。存储禁用或已满时保留当前页面内副本并提示，关闭前请自行复制。更新本版需重新构建并重启本地服务，再刷新工作台；扩展代码未改变。

## 0.6.4：精简界面

常规任务只保留一处状态、顶部 AI 名称、回复正文和操作按钮。澄清问题不再重复标题和操作说明；没有执行记录时不显示占位声明。接收诊断及浏览器模式下的手动导入默认折叠，展开状态不随接收进度更新而重置。断开连接、真实错误、Diff 批准、验证与回滚结果仍保留。仅更新前端，刷新工作台即可，服务与扩展无需重启或更新。

## 0.6.3：把澄清问题作为对话继续

- 模型返回符合协议、要求用户补充信息的回复时，任务进入 `needs_input`，显示「等待你补充信息」，不再冒充连接或执行失败。传输、解析、验证异常仍有独立错误处理；不根据错误文案猜测状态，也不重分类旧失败记录。
- 问题显示在独立卡片中，点击「回答模型的问题」即可进入当前对话的继续追问区。补充后重新读取项目文件并生成新的 Diff，仍需你审核；不会自动回答、重发或应用修改，也不消耗自动重试次数。
- 这个状态结束了本轮模型调用，但不是成功完成文件修改；可以归档、删除或开始其他任务。重启服务后保留问题，不把它改成中断失败；当前会话及历史轮次都支持这种状态。
- 最新接收诊断随会话保存，重启后以历史记录显示；继续新一轮时清除旧诊断，避免将上一轮状态误认为当前进度。仅保存已约束的版本、状态及数量字段，不新增正文采集。

本次更新工作台和本地服务，扩展仍为 0.8.14，无需更新扩展。编译后启动服务，刷新工作台确认 0.6.3。测试使用临时项目和模拟回复，不能替代真实模型网页验证。

## 启动

要求 Node.js 20 以上、pnpm 11。在项目源码根目录执行：

```powershell
pnpm install
pnpm build
pnpm web
```

在浏览器打开 `http://127.0.0.1:5000`。保留终端窗口；按 Ctrl+C 停止。

如果从其他目录调用，也可以执行 `node D:\Tools\OpenBrowser\dist\index.js web`。默认项目是启动时的当前目录，可以在网页中切换。

Windows 限制符号链接时，可尝试 `pnpm install --node-linker=hoisted`，随后重新构建。

## 页面能做什么

- **多模型协作**：选择2–4个提案者和1个评审，独立生成、匿名比较、人工选择并生成统一草案。点击「确认方案并生成 Diff」，核对最新源码和执行方式，创建关联实施任务；只有你单独批准 Diff 后才应用和验证。提案支持指定网页（扩展0.8.6）、手动及本机 Ollama；代码实施目前支持指定网页和手动。详见 [多模型协作指南](./COLLABORATION.zh-CN.md)。

- **发送与换行**：任务描述和继续追问输入框使用 Enter 发送、Shift+Enter 换行；中文输入法确认候选词不会误发。Ctrl/⌘+Enter 在这两个输入框中仍可发送；粘贴模型回复、搜索和项目地址输入不受此快捷键影响。
- **隐藏侧栏**：左上角 ☰ 按钮收起或展开导航侧栏，状态保存在当前浏览器；右上角“上下文”按钮控制文件侧栏。
- **对话菜单**：点击左侧每条对话右侧的“⋯”，可重命名、置顶/取消置顶、归档或删除。置顶会排在列表前面，归档可通过列表上方的“归档”找回，再从菜单“移回最近对话”。这些设置保存在本机，重启后仍然有效；不会更改原始提问。菜单支持方向键选择、Enter 执行、Esc 关闭，点击外部也会关闭。
- **删除旧对话**：从“⋯”菜单选择“删除”，核对标题后确认。删除整个本地会话（包括所有追问、回答和会话日志），无法恢复，刷新或重启后不会再次出现。不会删除项目文件、文件操作历史或模型网站上的聊天；进行中的任务必须先完成、停止或拒绝，再管理对话。

- **切换项目**：点击盘符、个人文件夹、子目录或“上一级”图形化浏览，到达项目目录后点击“选择此文件夹”。也支持输入绝对路径后点击“前往”。浏览不会上传文件，也不会修改终端当前目录。
- **项目上下文**：搜索文件、点击文件名只读预览、勾选文件附带源码。密钥和环境文件默认过滤，最多 30 个文件；过大文件会截断。项目摘要还包括结构和配置。
- **自动找代码**：在“修改代码”模式下可以不勾选文件，直接描述目标；模型可请求列目录、搜索关键词、按行读取。工具只有读取权限，不会自动修改文件。日志显示每次调用，最终方案仍须审核 Diff。详见 [文件发现工具](./FILE_DISCOVERY.zh-CN.md)。
- **任务工作台**：支持“修改代码”和“项目问答”；选择连接方式，输入任务并开始。
- **连续追问**：本轮完成、失败、取消或拒绝后，在回答下方的“继续追问”输入框发送下一轮，不需要新建任务。可以切换问答/修改代码、扩展/手动传递，并调整所选文件和验证脚本。
- **变更审核**：按文件查看真实 unified diff，批准或拒绝整轮方案；可导出 Diff。审批前不会修改项目文件。
- **运行日志**：查看当前步骤、验证输出、错误与重试过程；可导出日志。
- **历史记录**：读取当前项目最近 100 条本地操作记录。

界面采用黑白灰的简洁工作区：左侧导航和最近任务，中间任务与审核，右侧项目上下文。窄屏下点击顶部“上下文”或输入框下“添加上下文”打开文件面板。

任务顶部始终显示当前状态和下一步按钮，例如“粘贴模型回复”或“审核 Diff”。连接提醒位于任务输入框上方；输入错误显示在对应输入区，操作提示保留到手动关闭，不会一闪而过。任务进行中已附带的文件锁定，避免误以为新增勾选会改变本轮提示词。

## 两种模型连接方式

### 当前 AI 显示（扩展 0.8.5）

项目名称下方显示扩展报告的就绪 AI 平台，如 ChatGPT、DeepSeek、Claude 或 Gemini。多个页面同时就绪时列出候选平台，任务中以实际领取任务的 AI 为准；具体模型版本尚未识别，不会根据平台猜测型号。

每轮任务会保存实际接单平台，服务重启后仍可查看。手动传递或手动粘贴回复不能自动确认来源，不沿用浏览器平台标记。旧版扩展和旧记录未报告身份时明确显示未识别。

需要在扩展管理页重新加载当前源码中的 OpenBrowser Bridge **0.8.5**，再刷新 AI 网页与工作台。没有新增权限，只上报就绪页面的域名，不上报完整聊天 URL、页面标题或账号信息。

### 浏览器扩展

在 Chrome 的 `chrome://extensions` 开启开发者模式，加载源码中的 `browser-extension` 文件夹。登录一个受支持的 AI 聊天网页并刷新，工作台顶部会显示扩展连接状态。

多个 AI 标签页同时就绪时，在新任务或追问的“执行网页”中选择一个。本轮任务及后续工具补读、有限重试绑定该页面。扩展连接数表示桥接连接，不保证模型网页已经登录或可以接收任务。服务商报错、限流或认证失败时任务停止，由用户处理，不自动绕过限制。

v0.4 将连接状态区分为“扩展未连接”“扩展通道已连接（旧版）”“AI 页面未就绪”“AI 页面就绪”。新版扩展每 10 秒向本地服务报告心跳并探测网页输入框；实例 ID 保存在扩展本机存储中，不会因通道重连重复计数。心跳超过 45 秒没有更新后判定离线。页面就绪仅表示找到输入框，不保证账户、额度或模型服务可用。

未领取的任务可在通道恢复后重新投递，但已领取的任务不会自动再次发送，避免重复提交。等待回复超过 4 分钟会显示超时原因，由你决定继续追问或手动传递。Chrome 后台仍受浏览器休眠和系统资源策略影响，不能保证永不断线。相关背景见 [Chrome 扩展生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

### 从 v0.3 升级

1. 保存需要保留的回答，完成或停止当前任务。
2. 在原先启动工作台的终端按 Ctrl+C，随后在新版项目源码目录运行 `pnpm build`、`pnpm web`。默认服务地址仍为 `http://127.0.0.1:5000`，不要同时启动两个占用此端口的服务。
3. 打开 Chrome 的 `chrome://extensions`，找到 OpenBrowser Bridge 并点击重新加载。新版扩展版本为 0.8.3，要求 Chrome/Chromium 120 以上；没有新增权限。
4. 刷新已登录的 AI 网页，再刷新工作台，等待“AI 页面就绪”。仅刷新工作台无法更新旧的扩展脚本或服务代码。

新版服务会将会话自动保存在项目 `.openbrowser/workbench-sessions.json`，重启后重新加载。已完成会话可以继续追问；中断任务恢复为暂停，不会自动发送或应用。强制终止应用/验证时，必须先人工核查文件和操作历史；不要假定已经回滚。

### 手动传递

不需要浏览器扩展。在模型连接下拉框选择“手动传递”，开始任务后：

1. 点击“复制完整提示词”，把提示词发给你使用的模型。
2. 将模型完整回复粘贴回工作台，包括 JSON 操作头和文件内容。
3. 修改模式点击“生成 Diff，进入审核”；问答模式点击“显示回答”。问答模式只需模型文本，不需要 JSON。

手动模式同样使用真实协议校验、Diff、事务应用和验证，适合先熟悉流程或使用官方 API/本地模型的现成聊天工具。

## 在同一会话继续

本轮结束后，回答下方会出现“继续追问”。直接输入问题并发送；也可点击任务顶部的“继续追问”定位输入区。左侧只保留一条会话，前面的问答仍可阅读。

每次续聊重新读取所选文件，并携带最近最多 6 轮、总量不超过约 12,000 字符的历史摘要；不会重复发送旧 Agent 完整代码。重要要求应在当前问题中重申。整段会话最多 31 轮。每一轮的有限重试独立计数，修改方案仍需逐轮批准，拒绝的方案不会被当成已应用。按需片段与补读规则见 [上下文协议](./CONTEXT_PROTOCOL.zh-CN.md)。

等待回复、审核和应用期间不能直接发送下一轮；可以先停止或拒绝本轮。应用和验证期间不能停止事务。切换到其他项目后，需要先切回本会话所属项目，才能继续追问。

## 建议的第一次任务

打开一个你信任的小项目，选择一个源文件和对应测试文件，输入：

> 检查所选函数的边界条件，修复一个明确的问题，并补充对应测试。保持修改范围最小。

先看完整提示词，再审核 Diff。第一轮任务成功后再扩大上下文和修改范围。

## 审核、验证与重试

“应用后验证”会列出项目中存在的 `typecheck`、`test`、`lint`、`build` 脚本，默认选择存在的前两项。悬停可查看脚本命令。问答模式不执行验证。

批准后，系统先检查文件是否在生成 Diff 后被外部编辑；存在冲突就停止写入并请求新方案。执行或验证失败时，宿主尝试恢复本轮结构化文件修改，随后将错误反馈给同一任务，最多三次尝试。每轮新方案仍需审核；回滚失败会停止重试并在日志中显示。

验证在临时项目副本中运行，通常将依赖目录链接到原项目。Windows 或受限环境不允许链接时，自动改为复制依赖（首次可能较慢）；不会因此跳过测试、请求管理员权限或关闭系统保护。测试脚本仍有本机文件和网络权限；只有你信任的项目才能启用验证。副本不是容器级隔离。

验证只使用已有依赖，不自动安装。pnpm 的运行选项放在脚本名之前，避免作为参数误传给 TypeScript 等工具。依赖准备或工具启动失败属于环境问题：本轮回滚并停止，不再反复请求模型修改同一方案。修复环境后可复用已保存回复重新生成 Diff，仍需审核。

## 当前边界

- UI 使用本机服务；无遥测、无外部字体/CDN依赖。
- 同源请求和每次服务启动生成的令牌保护工作台 API；服务默认只绑定 `127.0.0.1`。
- 模型命令默认禁用，依赖安装、数据库迁移和部署由用户自行执行。
- 会话正文、模型回复、历史轮次和日志自动保存在项目 `.openbrowser/workbench-sessions.json`，文件操作历史保存在 `.openbrowser/history.json`。保存使用临时文件、同步和原子替换；仅保存在本机，未加密，分享项目时必须排除 `.openbrowser`。
- 实时连接、访问令牌、执行计划和批准状态不持久化。重启后旧方案不能直接应用，必须继续追问生成新方案或显式导入保存回复重新审核。切换项目时加载该项目的会话，不自动浏览其他项目。
- 当前一次只允许一个进行中的任务。应用与验证期间不能取消事务或切换项目。
- 历史手动回滚、ZIP 导入、官方模型 API、路由、子 Agent 与容器执行器尚未提供。
- 操作日志与模型回复显示为安全的纯文本；问答暂不渲染复杂 Markdown。

v0.3 界面复测：空任务和空回复的就地提示、项目路径错误提示、手动问答、修改提案与拒绝审核，以及桌面/390 px 窄屏上下文面板。切换审核页会返回页面顶部，避免下一步提示被旧滚动位置遮住。本轮界面验收未应用测试提案。

v0.4 自动化测试总计 20 项通过，新增同会话追问/模式切换/刷新源码/拒绝后继续、只读目录浏览、稳定实例计数/页面就绪、未领取任务重放、晚到回复保护和扩展超时重连/去重测试。浏览器实测完成两轮手动问答、就地追问校验、目录进入/返回/选择。扩展重连使用模拟浏览器接口验证，未向真实模型发送测试提示；实际网站兼容性需在重新加载新版扩展后确认。

v0.4.1 修复 Windows 验证准备阶段的 EPERM：依赖链接失败时复制依赖，不自动安装或跳过验证；修正运行选项顺序；环境故障不再触发模型重试。新增依赖复制/源文件保护、环境故障停止重试、保存回复恢复审核测试，共 23 项通过。已在实际受限环境完整运行临时副本的 `typecheck` 和 `test`。

v0.4.2 / 扩展 0.8.4 修复回复捕获：按 DeepSeek 片段类型和补丁路径组装最终答案，过滤思考片段，处理 BATCH 中的首个文本、SET/APPEND 和跨块换行；中断流不再当成完整回复。最终答案即使较短也覆盖中间文本，早于等待器到达的回复不会丢失。相关流式格式使用模拟数据测试，真实网站后续格式变化仍可能需要适配。

服务端仅在结构完整、只有一个操作头且会话编号匹配时，兼容缺少开头花括号/引号的旧版捕获结果；不猜补操作、文件内容或闭合符号。严格检查 JSON，忽略显式思考标签，保留路径限制、禁用命令和 Diff 审核。已加入此次失败原文回归，自动化测试共 38 项。

更新扩展后需在浏览器扩展管理页重新加载，再刷新 AI 网页；确认版本为 0.8.4。如果原先加载的是旧交付文件夹而非当前源码，单纯点击重新加载不会更新，请改用当前源码的 `browser-extension` 文件夹。浏览器端更新前，服务器的有限兼容解析也可恢复符合条件的既有回复，无需再次请求模型。
