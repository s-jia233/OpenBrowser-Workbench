# 自动发现项目代码

## 怎么用

1. 选择项目，切换到“修改代码”。
2. 可以不勾选文件，描述目标，例如：“查找登录失败的原因，提出最小修改，并补充相关测试。”
3. 模型可以请求列目录、搜索报错或函数名，再读取相关文件及行号。工作台日志显示这些只读操作。
4. 最终方案进入 Diff 审核。批准前不会修改文件；原有验证和回滚流程不变。

使用浏览器扩展时，工具请求和结果自动传递。手动传递时，每轮复制工作台更新后的提示词，粘贴模型完整 JSON 回复，直到生成待审核方案。命令行 Agent 也支持同一协议。问答模式目前仍是普通文本回答，不使用自动发现工具。

不勾选文件只表示“不预先附带源码”，不表示禁止读取项目。选择浏览器模型时，工具返回的允许范围内源码会发送给该模型服务；不应选择不允许外发的项目。

## 工具协议

模型每次只返回一个 JSON 对象。只读请求不能与修改、报错或旧式 `contextRequests` 混用。

```json
{
  "conversationId": "当前任务 UUID",
  "operations": [],
  "toolRequests": [
    { "tool": "list_files", "path": ".", "depth": 2 },
    { "tool": "search", "path": "src", "query": "LOGIN_FAILED" }
  ]
}
```

- `list_files`：项目相对目录，`.` 表示项目根；深度 1–4，默认 2。列出文件与目录，包括空目录，每次最多返回 80 项。
- `search`：项目相对文件或目录，默认根目录；关键词按字面匹配，不执行正则或命令。默认不区分大小写，可传 `caseSensitive: true`。最多返回 30 个命中，包含路径、原始行号、列号及最多 240 字符的摘要。
- `read_file`：相对文件路径，可同时传 `startLine`、`endLine`，每段最多 200 行；省略两项请求全文。结果进入带原始行号和内容摘要的源码上下文。

工具结果放入下一轮上下文的 `toolResults`，最近完整记录最多 8 条、合计最多约 20,000 字符。读取到的源码放入 `contextFiles`，不在结果摘要中重复发送。调用失败也以结果返回，模型可以在剩余额度内调整路径或关键词。

## 限制与安全

- 每个用户回合最多 6 轮只读工具请求，每轮 1–4 个工具；旧式补读最多 2 轮，也计入这 6 轮。只读步骤不占原本最多 3 次纠错尝试，达到上限暂停，用户可缩小任务后明确继续。
- 每轮目录/搜索最多检查 5,000 个目录项，搜索正文最多读取 8 MB，扫描有约 4 秒的协作式时间预算。不是能强制中断文件系统阻塞的硬超时。
- 单个源码文件读取上限 1 MB，补读后的上下文上限 140,000 字符。列表、搜索摘要和历史还有单独的返回大小上限。截断、跳过大文件等情况会明确标记；没有命中不代表所有被忽略或超限的文件都已扫描。
- 不访问项目外路径、符号链接、二进制正文、常见密钥和环境配置，以及依赖缓存、构建产物。固定规则不是完整的敏感内容识别系统，普通源码中主动写入的秘密仍需用户自行排除。
- 不调用 shell，不执行搜索结果中的文字，不新增扩展权限，不绕过服务配额。
- 搜索摘要仅用于定位，不能授权修改。自动发现流程中，编辑现有文件前必须读取相关源码；只读过片段时禁止整文件覆盖，补丁必须落在可见范围内。
- 纠错重试仍保留上述读取约束；工具读完后文件被外部修改，会要求重新读取。服务重启不会自动恢复工具执行或批准。

本批使用模拟模型协议、实际本地文件和工作台接口验证；第三方模型是否持续正确选择工具仍取决于其指令遵循能力，找不到内容时可手动附带文件。
